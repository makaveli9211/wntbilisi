# Утренняя сводка в Telegram — Тбилиси

Каждый день в **08:00 по Тбилиси** бот присылает подписчикам одно сообщение:

- **погода в Тбилиси по часам** на весь оставшийся день — температура, значок погоды и вероятность осадков на каждый час, плюс сводка дня: макс/мин, ощущается, осадки, ветер, УФ, восход и закат;
- **5** главных новостей;
- **2** новости про Грузию;
- **2** новости про рынки и финансы + курсы GEL/USD/EUR/RUB от Нацбанка Грузии;
- **2** новости про технологии и AI;
- **результаты вчерашних матчей** топ-лиг — Лига чемпионов, АПЛ, Ла Лига, Серия A, Бундеслига, Лига 1.

**Подписаться может кто угодно** — человек находит бота в Telegram, жмёт `/start` и со следующего утра получает сводку. `/stop` — отписаться. Список подписчиков бот ведёт сам.

**Язык у каждого свой.** По умолчанию грузинский; под приветствием две кнопки — 🇬🇪 ქართული и 🇷🇺 Русский, галочка стоит на текущем. Нажатие меняет язык только этому подписчику: в одной рассылке один читает по-грузински, другой по-русски. Есть и текстовые команды `/lang ka`, `/lang ru` — на случай, если кнопки кто-то потерял в переписке.

Локализовано всё: даты, дни недели, описания погоды, названия разделов, ответы бота — и сами источники новостей, для каждого языка свой набор лент, так что перевод не нужен.

Работает на GitHub Actions — свой сервер и включённый компьютер не нужны. Бесплатно: в публичном репозитории минуты Actions не тратятся вообще, в приватном придётся снизить частоту опроса — см. таблицу в `subscribe.yml`.

Зависимостей нет: только стандартная библиотека Python.

## Как это устроено

Три workflow и общий скрипт сохранения состояния:

| Файл | Когда | Что делает |
|---|---|---|
| `subscribe.yml` | каждые 5 минут | забирает команды `/start`, `/stop`, `/lang` и нажатия кнопок; бронирует и рассылает сводку, если сегодня она ещё не уходила |
| `daily.yml` | 04:00 UTC = 08:00 Тбилиси | то же по расписанию, плюс ручной запуск кнопкой |
| `drain.yml` | вручную | аварийно выбрасывает накопившуюся очередь Telegram |
| `.github/save-state.sh` | — | общий шаг сохранения `subscribers.json`, вызывается из всех трёх |

**Рассылка не привязана к одному срабатыванию cron.** GitHub выполняет расписание «по возможности» и регулярно пропускает запуски — особенно в ровный час, куда все ставят задачи. Поэтому в `subscribers.json` хранится отметка `last_digest`, и при каждом опросе бот спрашивает себя: сегодня уже отправляли? Если нет и время после `SEND_HOUR` — рассылает. Даже когда GitHub проглотит запуск в 04:00 UTC, сводка уйдёт на ближайшем следующем.

**Порядок внутри прогона важен: сначала бронь, потом отправка.**

```
--claim-day  →  записать бронь в репозиторий  →  --send-now  →  сохранить итог
```

Отметка о сегодняшней рассылке коммитится **до** того, как уйдут сообщения, и отправка выполняется только если коммит прошёл. Сохраняйся отметка после рассылки — непрошедший push (защита ветки, отозванный токен, сбой GitHub) означал бы, что каждый следующий запуск считает сводку неотправленной и шлёт её заново. Каждые пять минут. До вечера. При нынешнем порядке худший исход — сводка за день не уйдёт вовсе, что видно в логе и лечится кнопкой Run workflow.

### Состояние и слияние

Список подписчиков живёт в `subscribers.json` в самом репозитории — отдельная база не нужна, история изменений видна в коммитах.

Файл генерируемый, поэтому `git pull --rebase` для него не годится: на нём легко получить конфликт. Перед коммитом workflow забирает версию из репозитория и вызывает `bot.py --merge`, который объединяет списки по смыслу и кладёт результат ровно поверх удалённой ветки — конфликт при таком порядке невозможен.

Отдельная история — удаление. Простое объединение его отменяет: ключа, которого мы только что лишились, в удалённой версии он ещё есть, и человек возвращается в список. Поэтому отписки помечаются надгробиями в `removed`, а порядок событий определяется счётчиком `rev`: он растёт при каждом изменении и живёт в файле, так что подписка и отписка сравнимы, даже если пришли в одну секунду. Надгробия стареют за `TOMBSTONE_DAYS` (60 дней) и исчезают.

Состояние нормализуется при чтении: кривой `offset`, строка вместо записи подписчика, оборванная запись — всё это приводится к рабочему виду вместо падения. Файл лежит в репозитории и его правят руками, так что это не теория.

### Защита от дублей

Обработанные апдейты бот подтверждает в самом Telegram (`confirm_offset`), и тот удаляет их у себя. Если бы единственной защитой был `offset` в файле, любая неудачная запись приводила бы к тому, что следующий запуск заберёт те же команды снова и ответит на них по второму разу. Подтверждение уходит только после успешного сохранения, так что потерять команду тоже нельзя.

Плюс страховка на уровне прогона: на каждый чат отправляется не больше одного ответа каждого вида. Нажал кнопку пять раз — язык переключится, галочка переедет, новых сообщений не прибавится.

## Настройка — 6 шагов, ~15 минут

### 1. Создать бота

В Telegram напишите [@BotFather](https://t.me/BotFather):

```
/newbot
```

Придумайте имя и username (должен заканчиваться на `bot`). BotFather пришлёт **токен** вида `8123456789:AAH_kQx...`.

⚠️ Число до двоеточия — это id самого бота, а **не** ваш `chat_id`. Частая путаница.

### 2. Показать команды в меню бота

Там же у BotFather отправьте `/setcommands`, выберите своего бота и вставьте:

```
start - подписаться на утреннюю сводку
stop - отписаться
lang - язык / ენა
help - справка
```

Теперь у людей в диалоге появится кнопка «Меню» со списком команд.

### 3. Создать репозиторий

Распакуйте архив, затем:

```bash
cd tbilisi-daily-bot
git init && git add . && git commit -m "daily digest bot"
gh repo create tbilisi-daily-bot --private --source=. --push
```

Без `gh`: создайте пустой репозиторий на github.com и запушьте файлы обычным `git remote add origin ... && git push -u origin main`.

Загружаете через веб-интерфейс? Учтите, что drag-and-drop **не переносит папку `.github`** — она скрытая. Создайте оба файла вручную: **Add file → Create new file**, и в поле имени вставьте целиком `.github/workflows/daily.yml` — слэши сами превратятся в папки.

### 4. Разрешить workflow писать в репозиторий

**Settings → Actions → General → Workflow permissions →** выбрать **Read and write permissions** → Save.

Без этого бот не сможет сохранить список подписчиков: рассылка пройдёт, а коммит упадёт с `403`. У новых репозиториев по умолчанию стоит только чтение — проверьте обязательно.

### 5. Добавить секреты

**Settings → Secrets and variables → Actions → Secrets → New repository secret:**

| Name | Обязателен | Value |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | токен из шага 1 |
| `TELEGRAM_CHAT_ID` | нет | ваш личный id — этот чат получает сводку всегда, даже без `/start` |
| `FOOTBALL_API_TOKEN` | нет | ключ [football-data.org](https://www.football-data.org/client/register) для блока с футболом |

Свой id узнать: напишите [@userinfobot](https://t.me/userinfobot), он ответит числом. Если не нужно — секрет можно не создавать вовсе, подписки достаточно.

### 6. Проверить

Найдите своего бота в Telegram, нажмите **Start**. Затем **Actions → «Приём подписчиков» → Run workflow** — бот ответит приветствием, а в репозитории появится коммит с вашим id в `subscribers.json`.

Дальше **Actions → «Утренняя сводка в Telegram» → Run workflow** — придёт сама сводка. В выпадающем списке можно разово навязать всем язык, чтобы сравнить версии.

Всё, дальше работает само: приём подписчиков — каждые 5 минут, рассылка — каждое утро в 08:00.

## Приватность списка подписчиков

`subscribers.json` лежит в репозитории. **Если репозиторий публичный, id всех подписчиков видны любому** — по ним нельзя написать человеку или узнать его телефон, но это всё же утечка: видно, сколько у вас читателей и когда каждый подписался.

Поэтому:

- по возможности держите репозиторий **приватным** (Settings → General → внизу Change visibility). **но тогда обязательно снизьте частоту опроса** — при нынешних `*/5` приватный репозиторий съест ~8600 минут в месяц при лимите 2000. Для приватного ставьте `0 * * * *` (~720 мин) или `*/30` (~1450 мин), таблица есть в `subscribe.yml`;
- имена подписчиков не сохраняются вообще — за это отвечает `STORE_NAMES = False` в `bot.py`. Включайте только на приватном репозитории.

Токен и `chat_id` в секретах GitHub, в логи они не попадают.

## Локальный запуск и отладка

```bash
python bot.py --dry-run              # напечатать сводку, ничего не отправляя
python bot.py --dry-run --lang ka    # то же на грузинском
python bot.py --poll                 # разобрать команды и обновить subscribers.json
python bot.py --claim-day            # забронировать сегодняшнюю рассылку (код 20 = не нужно)
python bot.py --send-now             # разослать, не трогая отметку дня
python bot.py --if-due               # бронь и рассылка одним шагом (для локального запуска)
python bot.py                        # разослать всем подписчикам
python bot.py --lang ka              # разослать всем принудительно на грузинском
python bot.py --whoami               # показать chat_id тех, кто недавно писал боту
python bot.py --merge other.json     # влить в свой список чужую версию файла
python football.py                   # что отдаёт футбольный API: матчи и причины пустоты
python football.py ka                # то же, но блок на грузинском
```

Для всего, кроме `--dry-run`, нужен `TELEGRAM_BOT_TOKEN` в окружении.

Офлайн-проверка на подставных данных, сеть не нужна:

```bash
python test_offline.py
```

Собирает сводку на обоих языках и проверяет форматирование, почасовую таблицу, экранирование HTML, отсечение дублей и устаревших заголовков, разбор команд `/start` `/stop` `/lang`, рассылку по языкам, вычёркивание заблокировавших бота и сохранение списка.

## Что можно поменять

Всё в начале `bot.py`, в блоке «НАСТРОЙКИ».

### Почасовая таблица

```python
HOURLY_FROM = 7          # с какого часа показывать
HOURLY_TO = 23           # по какой час включительно
HOURLY_STEP = 1          # 1 = каждый час, 2 = через час, 3 = раз в три часа
HOURLY_SKIP_PAST = True  # не показывать часы, которые уже прошли
HOURLY_SHOW_WIND = False # добавить колонку с ветром
```

По умолчанию в 08:00 приходит таблица с 08:00 до 23:00 — 16 строк. Вероятность осадков в строке появляется только если она 20% и выше, чтобы сухие часы не пестрили нулями.

### Количество новостей

`COUNTS` — сколько пунктов в каждом блоке. `0` выключает раздел целиком:

```python
COUNTS = {"world": 5, "georgia": 2, "finance": 2, "tech": 0}
```

### Источники новостей

`FEEDS` — обычные RSS-ленты, отдельным набором на каждый язык. Нерабочая лента пропускается с предупреждением в логе, сводка всё равно уходит. Бот берёт заголовки по кругу из всех лент раздела, чтобы не было перекоса в один источник, отбрасывает дубли и всё старше 30 часов (`NEWS_MAX_AGE_HOURS`).

### Язык по умолчанию

`DEFAULT_LANG = "ka"` — что получают те, кто не выбирал сам. Есть нюанс: первый язык бот подбирает по языку клиента Telegram (`guess_lang`) — у кого интерфейс русский, тот сразу получит русскую версию, у остальных сработает `DEFAULT_LANG`. Дальше решают кнопки.

Подписи кнопок — в `LANG_BUTTONS`. Чтобы добавить третий язык, допишите блок в `STRINGS`, набор лент в `FEEDS` с тем же ключом и строку в `LANG_BUTTONS`.

### Город

`LAT`, `LON`, `TIMEZONE`.

### Время отправки

Строка `cron` в `.github/workflows/daily.yml`, **в UTC**. Тбилиси = UTC+4 круглый год, так что вычитайте 4 часа:

| Нужно в Тбилиси | cron |
|---|---|
| 07:00 | `0 3 * * *` |
| 08:00 | `0 4 * * *` |
| 09:30 | `30 5 * * *` |
| только по будням в 08:00 | `0 4 * * 1-5` |

## Футбол

Футбол живёт в отдельном файле `football.py`. Если его нет рядом с `bot.py` — сводка просто выходит без этого блока, всё остальное работает. Настройки (список турниров, лимит матчей, окно) тоже там, в начале файла.

Результаты берутся с [football-data.org](https://www.football-data.org/) — бесплатный навсегда тариф: 12 турниров, 10 запросов в минуту, нам нужен один в сутки. Регистрация занимает минуту, ключ приходит на почту, кладётся в секрет `FOOTBALL_API_TOKEN`. **Без ключа блок просто не появляется в сводке**, всё остальное работает как раньше.

Запрос уходит только с `dateFrom`, `dateTo` и `status=FINISHED` — **параметра `competitions` у эндпоинта `/v4/matches` нет**, лишний параметр он отвергает целиком. Нужные турниры отбираются уже на нашей стороне.

Показываются матчи, завершившиеся за последние 36 часов, сгруппированные по турнирам. Окно шире суток намеренно: матч, начавшийся поздно вечером, по UTC уезжает на следующую дату, и при жёстком «за вчера» поздние игры терялись бы.

Настройки в `bot.py`:

```python
COMPETITIONS = ["CL", "PL", "PD", "SA", "BL1", "FL1"]
MAX_MATCHES = 12      # максимум матчей в сводке
HOURS_BACK = 36       # какое окно считаем «вчера»
```

Доступные на бесплатном тарифе коды: `CL` Лига чемпионов, `PL` АПЛ, `PD` Ла Лига, `SA` Серия A, `BL1` Бундеслига, `FL1` Лига 1, `PPL` Примейра, `DED` Эредивизи, `ELC` Чемпионшип, `BSA` Бразилейрао, `WC` ЧМ, `EC` Евро. Порядок в списке задаёт порядок блоков в сводке.

Названия турниров переведены на оба языка, **названия команд остаются как их отдаёт API — латиницей**. Это осознанно: транслитерация клубов вручную быстро превращается в спор о том, «Бавария» или «Байерн», и на каждый новый клуб нужна новая строчка в словаре.

Почему не flashscore: у них нет открытого API, страница собирается JavaScript'ом, данные тянутся из внутренних эндпоинтов с защитой от ботов, а правила использования прямо запрещают автоматический сбор. Такой парсер ломался бы каждые пару месяцев.

## Про источники

**Русский.** Мир — BBC Russian, DW, Meduza, Euronews. Грузия — JAMnews (рус.), Civil.ge, OC Media. Финансы — Investing.com, РБК. Технологии — Habr, 3DNews, iXBT.

**Грузинский.** Главные новости — Радио თავისუფლება, Publika, On.ge. Грузия — Netgazeti, Civil.ge, раздел «Южный Кавказ» Netgazeti. Финансы — раздел «Экономика» Netgazeti, экономика Радио თავისუფლება.

Две оговорки по грузинской версии:

1. **Грузинские издания не делят ленты на «мир» и «Грузию»** — международную повестку публикуют вперемешку с местной. Поэтому первый блок называется не «Главное в мире», а «დღის მთავარი ამბები» — главные новости дня. Дубли между блоками отсекаются.
2. **Грузиноязычных лент про технологии практически не существует.** Этот блок в грузинской версии англоязычный — TechCrunch, The Verge, Ars Technica. Не нужно — поставьте `COUNTS["tech"] = 0` или подставьте в `FEEDS["ka"]["tech"]` русские ленты.

## Известные особенности

- **Бот отвечает не сразу.** Между `/start` или нажатием кнопки и ответом проходит несколько минут: при `*/5` обычно 5–15, потому что GitHub запускает cron с собственной задержкой и в часы пик может опоздать сильнее. Не нажимайте повторно в ожидании — впрочем, если нажали, дублей всё равно не будет. По той же причине «часики» на кнопке крутятся и гаснут сами: подтвердить нажатие Telegram разрешает лишь несколько секунд, а мы приходим позже. Язык при этом меняется исправно, и галочка на кнопке переезжает — просто с задержкой.
- **Задержка расписания.** GitHub Actions запускает cron не секунда в секунду: типично +0–20 минут. Если критична точность до минуты — нужен свой сервер с обычным cron.
- **Репозиторий засыпает.** В публичном репозитории без коммитов 60 дней GitHub отключает расписание и присылает письмо — достаточно нажать «Enable workflow». Здесь это почти не грозит: приём подписчиков сам делает коммиты. В приватном ограничение не действует.
- **Заблокировавшие вычёркиваются сами.** Если человек заблокировал бота или удалил аккаунт, Telegram вернёт ошибку, и он молча уйдёт из списка. Временные ошибки (500, таймаут) подписку не рвут.
- **Футбол пустой — это нормально.** В межсезонье и в дни без матчей блок просто не появляется. Отличить «нет матчей» от «сломался ключ» помогает лог: там всегда есть строка `[i] футбол: API вернул N матчей` либо `[!] футбол: HTTP 403 ...`. Локально то же самое покажет `python football.py`.
- **Ленты меняются.** RSS-адреса иногда переезжают. Если раздел приходит пустым — посмотрите лог запуска в Actions, там строки `[!] лента недоступна: ...`. Замените адрес в `FEEDS`.
